# Sonnet and Lumiere in Syllume

This directory contains the desktop Sonnet (商籟) and Lumiere (繪光) program compilers and Pixi renderers from [Folia](https://github.com/chthollyphile/folia-major/tree/3125d376557182e25a12c915e39099db13ba63c8), pinned to revision `3125d376557182e25a12c915e39099db13ba63c8`, under AGPL-3.0. Original comments and credits are preserved. `provenance.json` records original SHA-256 hashes plus documented iOS patch hashes.

The runtime patches allow the iOS host to cap the ticker at 60 or 30 fps. Both styles commit any in-flight song handover when paused and draw the new lyrics at the frozen media position. If Sonnet's icon preload finishes after a pause, it updates the same fixed frame without restarting the ticker. A timing patch preserves every grapheme of line-only lyrics with the same line start and end, giving both styles a shared line animation instead of invented word timing. Real word and syllable timestamps retain the original mapping.

The offline page signals when its bridge is installed. A navigation token identifies the current document in its messages and in the commands it receives, so queued work from a replaced document cannot update the current page. Debug iOS builds also supply a separate request token to time lyric program compilation, WebGL and Pixi setup, asset preparation, shader warmup, and the first frame. Elapsed times exclude track metadata and lyric text. Release emits no startup trace.

`entry.ts` replaces the React host with an offline WKWebView bridge. `stageController.mjs` reuses same-style runtimes for song and lyric changes, rejects late async creations, and renders no repeated paused frames. It consumes native absolute time and interpolates up to one second between corrections. Pausing, visibility changes, style replacement and teardown stop the ticker. Reduce Motion uses static frames. Lumiere currently receives zero audio-band values: its lighting and typography work, but this port does not claim live audio analysis or beat-synchronous light.

Balanced mode uses a 60 fps cap and bounded resolution; energy-saving or system Low Power Mode uses 30 fps, reduced render scale and Lumiere's lower graphics quality. The native atmosphere uses a separate 15 Hz canvas without an extra full-screen blur pass. These are cost limits, not measured device frame-rate guarantees.

The generated offline resource is committed at `../Syllume/Resources/SyllumeStage/`. Xcode needs no Node downloads. With Node 24+, run `npm ci`, `npm run build`, then `npm test`. CI tests the TypeScript timing utility and runs the handover regression with the pinned build dependencies. That regression exercises the real runtime methods with GPU and asset operations replaced by test doubles. WebKit integration runs separately in the iOS simulator. `node_modules/` and `build-graph.json` are local intermediates. The source snapshot contains only the two renderer dependency graphs, not the desktop application.

YouTube uses a separate visible official IFrame player. No audio extraction, account tokens, or remote code are passed to the lyric stage. The Debug-only media fixture exercises real WebKit audio pause and resume without contacting YouTube; it is excluded from Release.
